# 基于 go-playground/validator Tag 的静态校验代码生成器

## Summary

实现一个面向 HTTP/gRPC request DTO 的 Go 静态校验生成器：

- 规则声明统一使用 `go-playground/validator` 的 `validate:"..."` struct tag；
- 使用 `k8s.io/gengo/v2` 解析 Go 类型和字段 tag；
- 借鉴 Kubernetes 官方 `validation-gen` 的 validator registry、规则 IR、生成器和测试组织方式；
- 不直接依赖或 fork 完整 Kubernetes `validation-gen`；
- 默认生成无反射、可审查的 `Validate()`；
- 静态暂不支持的规则不静默忽略，默认生成期报错；
- 需要完整 validator 能力时，由调用方显式使用 runtime API；
- `json:",omitempty"` 只影响 JSON 序列化，不参与校验语义。

## Key Changes

### 1. 规则声明和公共 API

请求 DTO 使用：

```go
type CreateUserRequest struct {
    Name  string  `json:"name" validate:"required,min=3"`
    Email *string  `json:"email,omitempty" validate:"omitempty,email"`
    Age   int     `json:"age,omitempty" validate:"gte=0,lte=150"`
    Role  string  `json:"role,omitempty" validate:"oneof=admin user"`
}
```

默认值单独使用：

```go
type UserRequest struct {
    Role string `json:"role,omitempty" validate:"required" default:"guest"`
}
```

生成：

```go
func (x *CreateUserRequest) Validate() error
func (x *UserRequest) FillDefaults()
```

runtime fallback 提供独立入口：

```go
func Validate(
    ctx context.Context,
    v *validator.Validate,
    value any,
) error
```

`Validate()` 不调用 `FillDefaults()`，不修改接收对象；`FillDefaults()` 只填充零值并保持幂等。

### 2. 静态规则范围

v1 静态生成支持：

```text
required
omitempty
min
max
len
gt
gte
lt
lte
oneof
email
```

规则语义必须与固定版本的 `go-playground/validator/v10` 保持一致，尤其是：

- string 长度；
- pointer 和 nil；
- `omitempty` 短路；
- named type；
- 数值边界；
- `required` 与 struct 类型的行为。

以下规则先作为 runtime-only：

```text
required_if
required_unless
required_with
required_without
eqfield
nefield
gtfield
gtefield
ltfield
ltefield
dive
keys
endkeys
自定义 validator
struct-level validator
依赖数据库或外部服务的规则
```

静态生成器遇到不支持的规则时默认报错；runtime API 仍可执行完整 validator tag。

### 3. 类型和 presence 语义

v1 静态规则支持：

- string；
- bool；
- 有符号整数；
- 无符号整数；
- 浮点数；
- 上述类型的 named type；
- 上述类型的 pointer。

presence 规则：

```text
普通值字段：按 Go 零值判断
pointer 字段：nil 表示未提供，非 nil 表示已提供
```

示例：

```go
Name *string `json:"name,omitempty" validate:"omitempty,min=3"`
```

语义：

```text
nil     -> 跳过 min
ptr("") -> 执行 min，校验失败
ptr("a")-> 执行 min，校验失败
```

v1 不自动递归验证嵌套 struct，不支持 `dive`、map key、list item 和跨字段规则的静态生成。

### 4. 解析器和中间表示

使用 gengo parser 获取：

```go
types.Member.Tags
types.Member.CommentLines
types.Member.Type
```

解析 `validate:"..."` 和 `default:"..."` struct tag，建立项目自己的规则 IR：

```go
type Rule struct {
    Name string
    Args []string
}

type FieldRules struct {
    GoName   string
    JSONName string
    Type     *types.Type
    Rules    []Rule
}
```

解析器必须：

- 保留 validator tag 的规则名称和参数；
- 支持 `oneof=admin user`；
- 检查参数数量和类型；
- 拒绝空规则；
- 拒绝未知规则；
- 拒绝同一字段的冲突组合；
- 给出 package、type、field 和原始 tag 上下文；
- 不依赖 map 遍历顺序。

规则约束：

```text
required + omitempty -> 生成期报错
重复同名约束 -> 生成期报错
default 与 required/omitempty -> 允许
json:",omitempty" -> 不参与校验
json:"-" + validate -> 生成期报错
```

### 5. 生成器

生成器使用 gengo 完成：

```text
加载目标 package
    -> 定位指定 struct
    -> 读取 Member.Tags
    -> 解析 validate/default
    -> 类型检查
    -> 构建规则 IR
    -> 生成静态 Go 代码
    -> gofmt
    -> 原子写入输出文件
```

CLI：

```bash
go run ./cmd/valgen \
  -type=CreateUserRequest \
  -output=zz_generated.validation.go
```

支持多个 `-type`。

生成代码要求：

- 文件头包含 `Code generated by valgen; DO NOT EDIT.`；
- 字段顺序和规则顺序稳定；
- import 顺序稳定；
- 多次生成无 diff；
- 生成失败时不覆盖已有生成文件；
- 生成代码不使用反射；
- 生成代码只依赖公共错误包和必要的纯校验 helper。

### 6. 错误模型

公共错误类型：

```go
type FieldError struct {
    Field string `json:"field"`
    Code  string `json:"code"`
}
```

约束：

- 每个失败规则产生一个 `FieldError`；
- 同一字段的 `required` 失败时跳过其他规则；
- 字段顺序按 struct 声明顺序；
- 同一字段的规则顺序由静态注册表固定；
- `Validate()` 使用 `errors.Join` 聚合；
- 提供递归收集函数：

```go
func CollectFieldErrors(err error) []FieldError
```

对外字段路径优先使用 JSON 名称：

```text
name
profile.email
items[0].sku
```

错误字符串仅用于日志和调试，不作为 HTTP/gRPC 协议。

### 7. Runtime adapter

runtime 包负责：

- 调用 `validator.StructCtx`；
- 支持调用方传入自定义 `*validator.Validate`；
- 支持自定义规则、alias、`dive`、跨字段规则；
- 将 `validator.ValidationErrors` 转换为统一 `FieldError`；
- 使用 JSON tag 映射字段名；
- 不使用全局可变 validator；
- 不覆盖调用方已有的 validator 配置。

静态模式和 runtime 模式不在同一个 `Validate()` 中重复执行，避免重复错误和语义不一致。

### 8. 默认值

`default:"..."` 不作为 validator 规则。

v1 只支持基础标量默认值：

```text
string
bool
signed integer
unsigned integer
float
```

不支持：

```text
slice
map
struct
pointer
复杂表达式
```

默认值必须可在生成期解析；非法字面量、溢出和类型不匹配直接报错。

## Assumptions

- canonical validation source 是 `validate:"..."` struct tag；
- 不再使用 `// +validate:` 或 `+k8s:` 作为字段规则来源；
- Kubernetes `validation-gen` 只作为架构和实现参考，不作为完整运行时依赖；
- 直接依赖 `k8s.io/gengo/v2`；
- `go-playground/validator/v10` 仅用于 runtime adapter；
- 依赖版本必须固定，不使用 `@latest`；
- `Validate()` 默认只代表静态校验；
- runtime 校验必须显式调用；
- 未加 `validate` tag 的字段忽略；
- `json:",omitempty"` 不推断 optional；
- PATCH/gRPC presence 通过 pointer、optional 或 wrapper 类型表达；
- v1 不实现嵌套集合和跨字段静态规则；
- 当前工作区尚未检测到 Git 元数据，正式 PR 前需要先建立或关联 Git 仓库和分支。
