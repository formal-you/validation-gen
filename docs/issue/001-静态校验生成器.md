# Issue 001：基于 validator tag 的静态校验代码生成器

- 状态：open
- 创建：2026-08-22
- 里程碑：v1

## 背景

HTTP/gRPC request DTO 需要参数校验。直接依赖 `go-playground/validator` 运行时反射校验，
代码不可静态审查、规则与结构体声明分离；而完整引入 Kubernetes `validation-gen` 又过度耦合 k8s 语义。

需要一个自研生成器：**规则声明统一使用 `validate:"..."` struct tag，生成无反射、可审查的
`Validate()` 与 `FillDefaults()`**，同时保留 runtime 校验作为显式扩展入口。

## 需求

1. 使用 `k8s.io/gengo/v2` 解析 Go 类型、字段与 tag，不依赖/不 fork 完整 validation-gen。
2. 规则声明统一为 `go-playground/validator` 的 `validate:"..."` struct tag；默认值用 `default:"..."`。
3. 生成 `func (x *T) Validate() error`（`errors.Join` 聚合 `FieldError`）与 `func (x *T) FillDefaults()`；
   `Validate()` 不修改接收对象、不调用 `FillDefaults()`。
4. v1 静态规则白名单：`required`、`omitempty`、`min`、`max`、`len`、`gt`、`gte`、`lt`、`lte`、
   `oneof`、`email`；语义与固定版本 `validator/v10` 一致（string 按 UTF-8 长度、pointer/nil 语义、
   `omitempty` 短路、named type、数值边界）。
5. 不支持的规则（`required_if`、`eqfield`、`dive`、自定义 validator 等）在生成期报错，不静默忽略；
   runtime 入口显式提供完整能力。
6. 公共错误模型：`FieldError{Field, Code}`、`CollectFieldErrors`；对外字段路径使用 JSON 名称。
7. runtime adapter：`Validate(ctx, *validator.Validate, value)`，支持自定义 validator 实例、
   `dive`、跨字段规则、JSON 字段名映射。
8. 默认值：仅基础标量（string/bool/int/uint/float），生成期解析，非法字面量/溢出/类型不匹配报错。
9. 提供 HTTP/gRPC 示例与集成测试，README 说明规则白名单、runtime-only 规则与 `json:",omitempty"` 语义。

## 验收

- `go generate ./...`、`go test ./...`、`go test -race ./...`、`go vet ./...`、`go build ./...` 全绿。
- 生成文件再生成后无 diff（`git diff --exit-code`）。
- 静态与 runtime 对照测试（同一 DTO + 输入，比较通过/失败字段/rule code）通过。
- 不支持规则不会被静默忽略；生成代码无反射；HTTP/gRPC 示例通过。
- 详细规格见 `docs/spec/validation-gen.md`。
